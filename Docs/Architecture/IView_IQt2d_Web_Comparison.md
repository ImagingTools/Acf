# Анализ библиотек iview и iqt2d (ACF) и их аналогов в WEB-экосистеме (React и др.)

## 1. Введение

Данный документ содержит архитектурный и функциональный анализ библиотек **iview** и **iqt2d**, входящих в состав подсистемы визуализации `Acf` (`Include/iview`, `Include/iqt2d`), а также сопоставление их возможностей с современными технологиями веб-разработки (включая экосистему React, Canvas-движки и библиотеки машинного зрения).

---

## 2. Анализ библиотеки `iview` (2D View Framework)

Библиотека `iview` представляет собой объектно-ориентированный движок 2D-сцены, оптимизированный для задач машинного зрения (Machine Vision), метрологии, интерактивной разметки областей интереса (AOI/ROI) и вывода калиброванных изображений.

### 2.1. Архитектурная модель
- **Model-View-Observer (`imod` + `iview`)**: Графические фигуры (`iview::IShape`) выступают наблюдателями (`imod::IObserver`) над прилежащими геометрическими моделями данных (`imod::IModel`). Изменения в модели автоматически уведомляют фигуру через механизм масок изменений (`istd::IChangeable::ChangeSet`).
- **Слоистая структура сцены (`iview::IViewLayer`)**: Сцена разделена на специализированные слои:
  - `LT_BACKGROUND` — фоновые объекты (растры, подложки);
  - `LT_INACTIVE` — информационные фигуры без взаимодействия;
  - `LT_ACTIVE` — интерактивные редактируемые объекты;
  - `LT_CALIBRATION` — координатная сетка, калибровочные маркеры;
  - `LT_TOOLS` — временные инструменты измерений.
- **Буферизация (`iview::CDrawBuffer`)**: Поддержка раздельного кэширования статического фона и динамических слоев для оптимизации перерисовки.

### 2.2. Система координат и калибровка
- **Преобразование пространства (`iview::CScreenTransform`)**:
  - Инкапсулирует аффинную матрицу `i2d::CAffine2d` для перехода между логическими координатами сцены и координатами экрана/клиентского окна.
  - Поддерживает прямое (`GetScreenPosition`) и обратное (`GetClientPosition`) преобразование с кэшированием обратной матрицы.
- **Метрология и калибровка (`iview::CCalibratedViewBase`, `i2d::ICalibration2d`)**:
  - Связь с калибровкой оптической системы камеры.
  - Поддержка реальных физических единиц (миллиметры, микроны).
  - Адаптивная координатная сетка (`SetGridInMm`, `SetMinGridDistance`), автоматически меняющая шаг при зуме.
  - Измерительные линейки по краям вьюпорта (`iview::IRuler`).

### 2.3. Интерактивные фигуры (Shapes)
В библиотеке реализован развитый набор параметрических примитивов:
- **Базовые фигуры**: `CRectangleShape`, `CCircleShape`, `CArcShape`, `CPolygonShape`, `CPolylineShape`, `CStarShape`, `CParallelogramShape`.
- **Специализированные фигуры машинного зрения**:
  - `CAnnulusShape` и `CAnnulusSegmentShape` — кольцевые зоны и секторы колец (внутренний/внешний радиусы, начальный/конечный углы).
  - `CTubePolylineShape` — ломаная трасса с адаптивной шириной «трубы».
  - `CAffineTransformation2dShape` — визуальный интерактивный базис осей координат (5 узлов манипуляции).
  - `CImageShape` — отображение растрового изображения с поддержкой цветовых трансформаций и LUT-таблиц (`icmm::IColorTransformation`).
  - `CDistanceToolShape` — инструмент измерения расстояний между точками сцены.

### 2.4. Модель взаимодействия (Interaction & Hit Testing)
- **Детекция касания (`iview::ITouchable`)**: Состояния `TS_NONE`, `TS_INACTIVE`, `TS_TICKER` (попадание в маркер), `TS_DRAGGABLE`, `TS_AREA`.
- **Маркеры трансформации (Тикеры)**: Базовый класс `iview::CRectControlledShapeBase` реализует угловые и срединные ручки для масштабирования, сдвига и вращения с обратной связью курсора (`UpdateMousePointer`).
- **Событийный конвейер (`iview::IMouseActionObserver`, `iview::IDraggable`)**: Полноценная обработка drag-and-drop в логических координатах (`BeginLogDrag`, `SetLogDragPosition`).

### 2.5. Вьюпорт и навигация (`iview::CViewport`, `iview::CConsoleGui`)
- Навигация: плавный зум к курсору, масштабирование (Fit to view, Fit width/height, Unproportional fit), панорамирование (Pan), скроллбары.
- Встроенный миникарта-навигатор (`iview::CPopupNavigator`).
- Панель команд и переключения режимов отображения.

## 3. Анализ библиотеки `iqt2d` (Qt 2D Integration)

Библиотека `iqt2d` служит интеграционным звеном между движком `iview`, компонентной средой `Acf` (`icomp::CComponentBase`) и классическим Qt Widgets GUI.

### 3.1. Архитектурная роль
- **Обертка вьюпорта (`iqt2d::CViewProviderGuiComp`)**: Инкапсулирует `iview::CConsoleGui` в виде зарегистрированного компонента, предоставляющего интерфейсы команд (`ibase::ICommandsProvider`), калибровки (`i2d::ICalibrationProvider`) и провайдера вида (`iqt2d::IViewProvider`).
- **Связывание сцены (`iqt2d::CSceneBinderComp`, `iqt2d::IViewExtender`)**: Позволяет сторонним модулям декларативно подключать свои фигуры к общей 2D-сцене.
- **Отображение растра (`iqt2d::CImageViewComp`)**: Синхронизирует модель изображения с фоновым слоем вьюпорта.

### 3.2. Редакторы параметров фигур (`TShapeParamsGuiCompBase`)
Ключевая особенность `iqt2d` — шаблонный класс:
```cpp
template <class UiClass, class ShapeClass, class ModelClass>
class TShapeParamsGuiCompBase;
```
Он обеспечивает **строгую двустороннюю реактивную синхронизацию**:
1. При манипуляции мышью на канвасе (`iview::IShape`) обновляется модель данных (`imod::IModel`), которая через событие `UpdateGui` переписывает значения в спинбоксах формы.
2. При изменении значений пользователем в полях формы срабатывают Qt-слоты (`OnParamsChanged`), вызывающие `UpdateModel`, что моментально обновляет геометрию фигуры на канвасе.

Реализованы готовые панели параметров:
- `CRectangleParamsGuiComp`
- `CCircleParamsGuiComp`
- `CAnnulusParamsGuiComp` / `CAnnulusSegmentParamsGuiComp`
- `CPolygonParamsGuiComp` / `CPolylineParamsGuiComp`
- `CAffineTransformationParamsGuiComp`
- `CLine2dParamsGuiComp` / `CQuadrangleParamsGuiComp` / `CTubePolylineParamsGuiComp`

## 4. Сравнение с WEB-экосистемой (React и сопутствующие библиотеки)

Сам по себе **React** является декларативной библиотекой управления состоянием и DOM-деревом (аналог системы `QWidget` / `iqtgui`), но **не графическим движком**. Однако в веб-экосистеме существует зрелый стек библиотек для решения аналогичных задач.

### 4.1. 2D Canvas-движки (Прямые аналоги `iview`)

| Библиотека | Возможности и сходство с `iview` | Интеграция с React |
|---|---|---|
| **Konva.js** | **Наиболее точный концептуальный аналог `iview`**.<br>• Сцена разбита на `Stage` и `Layer` (аналог `IViewLayer`).<br>• Богатые примитивы: `Rect`, `Circle`, `Ring` (прямой аналог `CAnnulusShape`), `Arc`, `Line`, `Star`, `Image`.<br>• Встроенный **`Transformer`** — полный аналог тикеров `CRectControlledShapeBase` (8 ручек изменения размера + ручка вращения).<br>• Попиксельный хит-тестинг через оффскрин-буфер цвета, Drag & Drop, масштабирование к точке. | **`react-konva`** — официальная декларативная библиотека. Фигуры объявляются как компоненты React JSX: `<Stage><Layer><Ring .../><Transformer .../></Layer></Stage>`. |
| **Fabric.js** | Высокоуровневая объектная модель поверх HTML5 Canvas.<br>• Рамка выделения с ручками трансформации по умолчанию для каждого объекта.<br>• Группировка объектов, множественное выделение, выравнивание.<br>• Сериализация сцены в JSON/SVG. | Используется в React через кастомные хуки или обертки (`react-fabricjs`). |
| **Paper.js** | Векторный математический фреймворк.<br>• Сильная сторона: кривые Безье, булевы операции над контурами (объединение/пересечение полигонов).<br>• Меньше готовых UI-виджетов манипуляции, чем в Konva, но выше математическая гибкость. | Монтируется в стандартный `<canvas>` через `ref`. |
| **PixiJS** | WebGL/WebGPU 2D-движок с экстремальной производительностью.<br>• Подходит для отображения сотен тысяч примитивов или тяжелых спрайтов с частотой 60+ FPS.<br>• Интерактивные манипуляторы (тикеры) требуется реализовывать вручную. | `pixi-react` |

### 4.2. Метрология, медицинские и CV-инструменты

Если требуется строгая калибровка и измерительные инструменты:
- **Cornerstone3D (Cornerstone.js) + Cornerstone Tools**:
  - Промышленный стандарт в вебе для медицинских и научных изображений.
  - Поддерживает **калибровку систем координат** (World $\leftrightarrow$ Canvas), субпиксельные измерения.
  - «Из коробки» содержит: линейки (Distance Tool), угломеры, эллиптические и полигональные ROI, калибровочные сетки.
- **OpenSeadragon + Annotorious**:
  - Предназначен для работы с гигапиксельными тайловыми изображениями и их разметки (полигоны, прямоугольники).

### 4.3. Реализация аналога `iqt2d` в React

В C++ архитектура двустороннего связывания требует десятков строк связующего кода (`imod::IObserver`, `UpdateModel`, `UpdateGui`). В React благодаря однонаправленному потоку данных и реактивности этот паттерн реализуется значительно проще:

```
                  ┌────────────────────────────────────────┐
                  │          Единый State (Zustand)        │
                  │  { x, y, innerRadius, outerRadius }    │
                  └──────────────────┬─────────────────────┘
                                     │
           ┌─────────────────────────┴─────────────────────────┐
           ▼                                                   ▼
┌─────────────────────────────────┐         ┌─────────────────────────────────┐
│     Холст (react-konva)         │         │   Панель формы (Mantine / MUI)  │
│  <Ring .../>                    │         │  <NumberInput label="Inner R" />│
│  <Transformer .../>             │         │  <NumberInput label="Outer R" />│
│  onTransformEnd -> updateState  │         │  onChange -> updateState        │
└─────────────────────────────────┘         └─────────────────────────────────┘
```

## 5. Ответ на вопрос: «Есть ли в WEB всё из коробки?»

**Ответ: Нет, не всё в виде единого готового решения.**

В веб-экосистеме доступен мощный **базовый конструктор (60–70% функционала)**, но оставшиеся **30–40% предметной логики машинного зрения и метрологии** требуют собственной разработки.

### Что есть «из коробки»:
1. **Движок холста**: рендеринг, сцены, слои, перерисовка, события мыши/тача (`Konva.Stage`, `Konva.Layer`).
2. **Базовые фигуры**: прямоугольники, круги, кольца, линии, полигоны, картинки.
3. **Стандартный манипулятор (Bounding Box Transformer)**: ручки масштабирования и вращения для прямоугольных областей.
4. **Реактивный биндинг**: автоматическая двусторонняя синхронизация между инпутами формы и фигурой на холсте.
5. **Навигация**: зум к курсору и панорамирование сцены.

### Чего «из коробки» НЕТ (требует кастомной разработки):

1. **Нестандартные составные манипуляторы (тикеры)**:
   - В веб-библиотеках `Transformer` рассчитан только на габаритную рамку (AABB / OBB).
   - Манипуляторы для `CAnnulusSegmentShape` (изменение начального/конечного угла прямо на дуге сектора), `CTubePolylineShape` (толщина трубы вдоль сегментов) или `CAffineTransformation2dShape` (координатный базис с 5 точками) придется создавать вручную через невидимые интерактивные опорные точки (`Konva.Circle`) с математическими ограничениями.
2. **Физическая калибровка в миллиметрах**:
   - Web-холсты работают в экранных пикселях.
   - Математику перевода пикселей в физические миллиметры с учетом аффинных искажений камеры и адаптивную метрическую сетку с масштабируемыми делениями (1 мм, 0.5 мм, 0.1 мм) придется реализовывать самостоятельно.
3. **Промышленные растры и аппаратные LUT**:
   - Стандартный HTML5 Canvas рассчитан на 8-битный RGB.
   - Промышленные 10/12/16-битные монохромные изображения с камер, а также динамическое наложение таблиц пересчета яркости/контраста (LUT / `icmm::IColorTransformation`) потребуют кастомного шейдерного рендера на **WebGL / WebGPU**.
4. **Специализированная верстка панелей**:
   - Формы редактирования параметров под каждую фигуру верстаются вручную (хотя на React это пишется существенно быстрее, чем на Qt Widgets).

## 6. Сводная таблица сравнения

| Функция / Требование | Решение в ACF (`iview` + `iqt2d`) | Решение в Web-экосистеме | Степень готовности в Web |
|---|---|---|---|
| **Движок сцены и слои** | `CViewBase`, `IViewLayer` | `Konva.Stage`, `Konva.Layer` | **100% (из коробки)** |
| **Базовые фигуры AOI** | `CRectangleShape`, `CCircleShape`, `CAnnulusShape` | `Konva.Rect`, `Konva.Circle`, `Konva.Ring` | **100% (из коробки)** |
| **Стандартный Bounding Box ресайз/поворот** | `CRectControlledShapeBase` | `Konva.Transformer`, ручки `Fabric.js` | **100% (из коробки)** |
| **Сложные манипуляторы (углы дуги, трубки, базисы)** | Написаны в `iview` | Создание кастомных контроллеров поверх `Konva.Group` | **Требует разработки (~30%)** |
| **Двустороннее связывание формы и фигуры** | `TShapeParamsGuiCompBase` (C++ Observer) | React state / Zustand + UI компоненты | **100% (из коробки, проще C++)** |
| **Калибровка в мм, физическая сетка** | `CCalibratedViewBase`, `i2d::ICalibration2d` | Кастомный Canvas-слой или адаптация `Cornerstone3D` | **Требует разработки (~50%)** |
| **Линейки и инструменты измерений** | `IRuler`, `CDistanceToolShape` | `Cornerstone3D Tools` или кастомная линия | **Частично доступно** |
| **16-битные промышленные растры и LUT** | `CImageShape`, `icmm` | WebGL / WebGPU шейдерная текстура | **Требует разработки (~40%)** |

## 7. Рекомендуемый технологический стек для Web

Если планируется реализация веб-версии или аналога `iview` / `iqt2d`:

1. **Базовый UI и состояние**:
   - **React 18/19** + **TypeScript**.
   - **Zustand** — для реактивного управления геометрическими моделями фигур.
   - **Mantine** или **Ant Design** — для панелей параметров фигур (числовые спинбоксы, слайдеры, селекторы).
2. **2D-графика и интерактив**:
   - **`react-konva` (`Konva.js`)** — идеальная база для векторных фигур, слоев, зума, панорамирования и базовых манипуляций.
3. **Вывод тяжелых изображений (при необходимости)**:
   - Отдельный фоновый слой на **WebGL** (или через шейдеры в PixiJS / Three.js) для 16-битных кадров и применения динамических LUT, поверх которого монтируется слой `react-konva` с геометрическими фигурами.
